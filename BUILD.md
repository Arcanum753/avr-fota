# Памятка: как происходит сборка

Короткая шпаргалка по процессу сборки прошивки. Понятным языком, без глубоких деталей.

---

## 1. Короткая шпаргалка команд

```bash
# 1) Выбрать окружение (env) — например esp32_clock-mech
# 2) Сгенерировать список модулей под ЭТО окружение:
python python/module_registry_gen.py --env esp32_clock-mech

# 3) Собрать:
pio run --environment esp32_clock-mech
```

> ⚠️ **Важно.** Список модулей (`src/modules_registry.cpp`) привязан к одному окружению.
> При смене env — обязательно перезапустить шаг 2, иначе сборка упадёт на линковке.

---

## 2. Что такое «список модулей» и зачем его генерировать

Проект состоит из множества модулей: WiFi, NTP, OTA, дисплей, часы (DS3231), шаговики и др.
В **конкретную прошивку** попадают не все — только те, что включены в настройках этого окружения.

Раньше соединение модулей было вручную прописано в коде с кучей `#if defined(...)`.
Теперь это делает Python-скрипт **автоматически**:

1. Читает `platformio.ini` и все дополнительные ini-файлы модулей.
2. Определяет, какие модули нужны для выбранного env (по правилу `src_filter`).
3. Для каждого модуля читает его «паспорт» — блок `[registry]` в его ini
   (имя объекта, флаги «есть веб-страница», «есть периодическая задача»).
4. Создаёт два файла: `src/modules_registry.h` и `src/modules_registry.cpp`.

В `modules_registry.cpp` лежит аккуратный список функций «запустить ядра /
запустить модули / запустить устройства», без `#if` — только нужные модули.

---

## 3. Что происходит на компиляции (`pio run`)

PlatformIO автоматически выполняет скрипты в заданном порядке.

**Пре-скрипты (до компиляции, порядок = номер файла):**
- `1_registry_pre_build.py` — генерирует список модулей `modules_registry.cpp/.h` под текущий env.
- `2_version_builder.py` — пишет версию прошивки в `src/version.h`.
- `3_module_version_gen.py` — версии модулей (меняются при изменении кода модуля).
- `4_fs_builder.py` — собирает «веб-образ» файловой системы в `web_debug/<env>/`,
  и вызывает `gen_page_head.py` (меню сайта).
- `5_set_fs_data_dir.py` — подставляет эту папку PlatformIO для сборки файловой системы.

**Параллельно:**
- компилируется весь C++-код, включая сгенерированный `modules_registry.cpp`;
- собирается прошивка `firmware.bin` и файловая система `littlefs.bin`.

**Пост-скрипты (после компиляции):**
- `6_copy_fw.py` и `7_copy_fs.py` — кладут готовые бинарники в папку `proj_fwbins/`.

## 4. Как модули запускаются при старте прошивки

В `setup()` вызывается `ESPHTTPServer.begin(&LittleFS)`. Внутри неё через registry:

1. Заполняется общий «контекст» `g_ctx` (файловая система, hostname, пароль).
2. Запускаются **ядра** в строгом порядке:
   JSON → WiFi → NTP → редактор → OTA / OTA-клиент.
3. Запускаются **модули** (например, DS3231, I2C-сканер).
4. Запускаются **устройства** (часы, кольцо) — после модулей.
5. Регистрируются веб-страницы каждого модуля.

В цикле `loop()` через `core_loop() / modules_loop() / dev_loop()`
вызываются периодические задачи (например, OTA-клиент).

---

## 5. Куда смотреть, если сборка сломалась

| Симптом | Причина |
|---|---|
| Линковка «не находит символ» | Список модулей не перегенерирован под этот env |
| Сбились настройки WiFi при прошивке | Порядок инициализации (JSON должен запускаться первым) |
| Не регистрируются веб-страницы модуля | В ini модуля не стоит `web = 1` в секции `[registry]` |

---

## 6. Как добавить новый модуль

1. Создать папку `src/module_xxx/` (взять за основу `src/module_template/`).
2. Добавить `module_xxx.ini` в проект и в `extra_configs` в `platformio.ini`.
3. В этом ini указать секцию `[registry]`:
   ```ini
   [registry]
   object = ModClassXxx
   define = MODULE_XXX
   web = 1
   loop = 0
   ```
4. Перегенерировать список под нужный env и собрать. Готово.
