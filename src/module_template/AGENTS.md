# module_template — шаблон нового модуля

> **Опциональный модуль.** Подключается через `src_filter` (define-флаг `MODULE_TEMPLATE`
> выводится из `src_filter` автоматически, в `build_flags` его указывать не нужно).
> **Работоспособен только в составе сборки, содержащей ядро** (см. `../../TRS.md` §2.1).

Эталонный пример опционального модуля: два GPIO-выхода (мигание), конфиг с массивом,
AJAX-страница с использованием общих `GetJson.js`/`GetMarkup.js` и терминальные команды
(`templ`) с проверкой аргументов и явным сохранением. Служит образцом для
создания новых модулей — при разработке копировать эту папку и переименовывать.

- **Репозиторий:** входит в ядро (не клон)
- **Папка:** `src/module_template/`
- **Флаг активации:** `MODULE_TEMPLATE` (генерируется в `src/modules_defines.h` из `src_filter`)
- **Registry:** `object=module_template`, `define=MODULE_TEMPLATE`, `web=1`, `loop=0` (без `namespace`/`res`/`prio`)
- **Только для платформы:** обе (ESP8266/ESP32)
- **Зависит от модулей:** —
- **Зависит от ядра:** `core_web`, `core_sys`, `core_json`

## Назначение

Эталонный пример опционального модуля — два GPIO-выхода (мигание), конфиг с массивом,
AJAX-страница с `GetJson.js`/`GetMarkup.js`.

## Функциональные требования

- FR-TEMPLATE-1: Образец структуры: `.h` + `.cpp` (шаблонный блок) + `_types.h` + `_engine.cpp` + `web/`.
- FR-TEMPLATE-2: Образец порядка функций: INCLUDES → объекты → `setFs` → `begin`/`begin(ctx)` → `web_Init` → веб-обработчики → конфиг → версии → логика.
- FR-TEMPLATE-3: Образец паттернов: AJAX-сохранение без перезагрузки, чтение/запись массивов JSON, отложенное сохранение.
- FR-TEMPLATE-4: Не включать в реальные сборки как функциональный модуль (только эталон).
- FR-TEMPLATE-5: Образец терминальных команд: `terminalRegister()` из `begin()`, дескриптор
  компонента, подкоманды с проверкой числа аргументов и диапазонов, `helpText` в `PROGMEM`,
  разделение apply/save (`templ save` — единственная запись на FS).

## Веб-интерфейс

Маршруты: `POST /template/save`, `POST /template/save_demo`, `GET /template/info`,
`/template/time`, `/template/ver`.
Страницы `template.html`, `template2.html`, `_menu.html`; конфиг `web/config_template.json`.

Таблицы шаблона используют `class="global_table_style"`. Новые страницы обязаны следовать
правилу единого стиля таблиц из корневого `AGENTS.md`: без локальных стилей таблиц, с
обёрткой `.content` + `overflow-x: auto`, числовыми колонками `align-right` и действиями под
таблицей для интерактивных списков.

## Конфигурация

`/config_template.json` — `gpio1State`, `gpio2State`, `blinkInterval`, `demoSampleText`,
`demoArray[3]`.

`demoArray` — только демонстрация паттерна `is<JsonArray>()`; в реальном модуле заменить
на свои поля или удалить.

## Терминал

`module_template_terminal.cpp` — эталон терминальных команд для остальных компонентов.
Регистрация — `terminalRegister()` из `begin()` после загрузки конфига. Команда верхнего
уровня — `templ` (сокращение; сам модуль в коде и документации везде называется `template`),
`component = "module_template"` (по нему `sys stat` ставит флаг `term`).

| Подкоманда | Назначение |
|---|---|
| `templ show` | GPIO1/GPIO2, период моргания, текст, массив, `Config: saved/modified` |
| `templ gpio <1\|2> on\|off\|toggle` | применить состояние выхода (2 аргумента: enum + инверсия) |
| `templ blink <0..60000>` | период моргания, мс; `0` — выключить |
| `templ text [<text>]` | показать/задать демо-текст; `""` очищает |
| `templ save` | сохранить `config_template.json` |
| `templ help` | справка |

Правила, которые демонстрирует шаблон:

- изменения из терминала только применяются в памяти и на железе; на FS пишет только
  `templ save` (правило apply/save из корневого `AGENTS.md`), веб-страница сохраняет сразу;
- `_configDirty` показывает в `show`, есть ли несохранённые изменения, и сбрасывается
  только при успешной записи;
- каждая подкоманда проверяет число аргументов и диапазон (`parseIntStrict`, `parseOnOff`);
  лишние токены — ошибка, а не молчаливое игнорирование;
- `helpText` лежит в `PROGMEM`, обработчики — статические методы класса с прямым доступом
  к приватным полям (`_config`), без публичных сеттеров;
- единая политика применения GPIO — `applyGpioTarget()`: при выключенном моргании
  состояние применяется сразу, при включённом — на ближайшем тике таймера; метод используют
  и терминал, и веб-обработчик;
- `templ text` без аргумента или из одних пробелов показывает текущее значение; очистка —
  только явным `""`;
- блокирующих операций нет: `blink` перезапускает таймер через `applyBlinkTimer()`, которая
  используется и веб-обработчиком.

### Как добавить `terminalRegister()` в новый модуль

1. В `begin()` (после загрузки конфига) вызвать `terminalRegister();`.
2. В `.h` объявить `void terminalRegister();` и статические обработчики
   (`s_terminalCmd`, при необходимости `s_cmdXxx`).
3. Создать `<module>_terminal.cpp`; подключить `core_terminal/core_terminal.h` и
   `core_terminal/common_module.h`.
4. Задать `kXCommands[]` для `help` и `kXHelp[] PROGMEM`; команда верхнего уровня — не
   длиннее 8 символов.
5. Вызвать `TerminalRegisterModule("<каталог>", "<команда>", "<описание>",
   &CLASS_X::s_terminalCmd, kXCommands, kXHelp, true)`; `component` должен точно совпадать
   с именем каталога.
6. В `s_terminalCmd()` без аргумента и для `help` печатать `kXHelp`; остальные ветки
   валидируют аргументы; неизвестная подкоманда — сообщение с подсказкой `<команда> help`.
7. Если изменение должно пережить перезагрузку — добавить явную подкоманду `save`
   (терминал не должен перезаписывать конфиг неявно).

## Слоистая структура

Из `../../LAYERS.md`: `module_template` — шаблон optional-модуля (эталон структуры);
demo-логика в `.cpp`; выделить `_types.h`, `_engine.cpp` (показать паттерн).

Ожидаемый набор файлов (см. `../../LAYERS.md`):

```
module_template_types.h   — define'ы и struct/enum
module_template.h         — класс CLASS_MODULE_TEMPLATE, debug-макрос, extern, Page_*
module_template.cpp       — шаблонный блок (begin, web_Init, обработчики, конфиг, версии)
module_template_terminal.cpp — терминальные команды (эталон для остальных компонентов)
module_template_engine.cpp — исполнительная логика
module_template.ini       — env-пример + секция [registry]
web/                      — template.html, template2.html, _menu.html, config_template.json
```

Пример секции `[registry]` (из `module_template.ini`):

```ini
[registry]
object = module_template
define = MODULE_TEMPLATE
web = 1
loop = 0
```
