# Модуль macros — сценарии на Tcl + встроенный cron

Модуль `module_macros` превращает прошивку AVR-FOTA в устройство с **пользовательскими
сценариями**: файлы-сценарии на языке Tcl с планировщиком по типу Cron. Сценарий может
«срабатывать по моменту времени» (cron), «по условию» (фронт ложь→истина) и «по событию»
(слово из терминала / кнопка). Модуль — прототип и каркас для дальнейшего расширения
(команды на GPIO/устройства и т.п.).

Содержимое:
- веб-страница-менеджер файлов сценариев (`/macros.html`);
- набор Tcl-сценариев в папке файловой системы `/macros/*.tcl`;
- Tcl-интерпретатор **pTcl** (`tcl.c`, вендоренный и доработанный);
- планировщик cron на базе **ccronexpr** (supertinycron) + time-мост на `common/TimeLib`;
- метафайл `/config_macros.json` (список, приоритеты, состояния, даты создания);
- отладка и управление через терминал (команды `macro ...`).

---

## 1. Что это и зачем

Прошивка получает гибкую «логику пользователя», которую не нужно перекомпилировать:

```
Пользователь пишет файл-сценарий на Tcl:
    cron {*/10 * * * * *}  { puts {tick every 10s} }
    term {temp 25}         { report {sensor: temp 25} }

Модуль при запуске сценария разбирает файл в «таблицу условий и моментов времени»,
а тик раз в секунду проверяет:
  — совпал момент времени?    → выполнить тело cron-правила;
  — условие стало истинным?    → выполнить тело cond-правила (по фронту);
  — пришло событие из терминала/веба → выполнить тело term/button-правила.
```

Все правила одного файла живут в **одном интерпретаторе**: `proc`, переменные,
счётчики сохраняются между срабатываниями.

## 2. Как подключить и собрать

Окружения-прототипы уже описаны в `src/module_macros/module_macros.ini`:

```ini
[env:esp32_macrotest]
extends = env:esp32
src_filter = ${platformio.src_filter} +<module_macros/> +<module_udp/> +<module_otaclient/>
build_flags=
    -D CONNECTION_LED=2
    -D AP_ENABLE_BUTTON=-1
    -D USE_LITTLEFS
    -D MODULE_UDP=1
    -D MODULE_MACROS=1
    -D DEBUG_MACROS=1
    -D MODULE_OTACLIENT=1
    -D DEBUGLOG_WIFI
    -D RELEASE
```

Сборка (файл `src/modules_registry.cpp` автогенерируется под выбранный env):

```bash
python python/module_registry_gen.py --env esp32_macrotest
pio run -e esp32_macrotest
```

Флаги макрос-окружений:
- `DEBUG_MACROS` — журнал модуля (не гейтится `RELEASE`);
- `RELEASE` — гасит общие логи (`DEBUGLOG` core_web/json), остаются только macros и wifi;
- `DEBUGLOG_WIFI` — логи Wi-Fi.

После прошивки:
1. Модуль создаёт каталог `/macros/` (если его нет). Файлы-примеры приходят с файловой
   системой (см. `src/module_macros/web/macros/*.tcl`), `fs_builder.py` раскладывает их
   в образ FS с сохранением подкаталога.
2. При первом проходе список файлов синхронизируется с метафайлом `/config_macros.json`
   (новые `.tcl` добавляются с приоритетом 7 и в состоянии «стоп», записи об отсутствующих
   файлах удаляются).
3. Откройте `/macros.html` или воспользуйтесь терминалом.

## 3. Веб-страница `/macros.html`

Страница-менеджер файлов сценариев.

### Таблица-список
Колонки (порядок можно менять, перетаскивая заголовки; порядок сохраняется в
`localStorage` браузера):
- чекбокс выбора;
- **приоритет** (0 — высший, 7 — низший);
- имя файла;
- размер;
- состояние: «запущен» / «стоп» / «ошибка» (текст ошибки — в всплывающей подсказке);
- дата создания.

Клик по строке выделяет её (подсветка). Двойной клик по строке открывает файл в
редакторе (`edit.html`, новая вкладка).

### Кнопки панели (сверху)
- **Обновить список** — перечитать `/macros/list` вручную (авто-опроса нет, чтобы не
  грузить устройство);
- **Создать** — создать новый файл (`new_macros.tcl`, при занятости имени — с номером);
- **Запустить** / **Остановить** — по выбранным (работают и для группы);
- **Перечитать** — перечитать выбранный сценарий (или все) — пересборка происходит в
  фоне (в течение ~1 с тиком);
- **Редактировать** — открыть выбранный файл в `edit.html`;
- **Переименовать** — имя файла в строке становится полем ввода;
- **Приоритет − / +** — изменить приоритет выбранного файла;
- **Удалить** — удалить выбранные (всегда с подтверждением).

Правила активности: «Запустить/Остановить/Удалить» активны при ≥1 выбранном,
«Редактировать/Переименовать/Приоритет±» — при ровно одном. Активные кнопки — зелёные,
неактивные — серые. Во время любого запроса рядом с кнопками мигает «…».

### Веб-API (все — GET, состояние в query)
| URL | Назначение |
|-----|-----------|
| `/macros/list` | JSON-список файлов |
| `/macros/create?name=` | создать файл сценария |
| `/macros/delete?name=` | удалить (имена через запятую) |
| `/macros/rename?old=&new=` | переименовать |
| `/macros/state?name=&on=1|0` | запустить/остановить |
| `/macros/prio?name=&dir=+1|-1` | изменить приоритет |
| `/macros/reload?name=` | перечитать (без name — все) |
| `/macros/fire?type=&token=` | внешнее событие (резерв) |
| `/macros/ver` | версия модуля |

Файлы `.tcl` открываются в `core_editor` (`edit.html`) как текстовые (расширение `tcl`
добавлено в распознавание текста редактора).

## 4. Терминал

Команды регистрируются модулем лениво при первом вызове `TerminalLoop()`. Общий вид:

```
macro list                         — список сценариев и число правил
macro run <file.tcl>               — запустить сценарий
macro stop <file.tcl>              — остановить
macro reload [file.tcl]            — перечитать (без имени — все)
macro prio <file.tcl> <+1|-1>      — изменить приоритет
macro msg <слова...>               — событие для term-правил (полное совпадение всех слов)
macro btn <имя...>                 — событие для button-правил
```

Пример:

```
macro run ex_input.tcl
macro msg temp 25
   → [MACRO] event term "temp 25" queued
     [MACRO] condition term "temp 25" fired
     [MACRO] 18:05:38
     [MACRO] sensor: temperature 25
macro btn start
   → [MACRO] condition button "start" fired
     [MACRO] button start pressed
```

Примечания: вывод в терминале — только латиница; сообщения модуля начинаются с
`[MACRO]`; тело правила печатается командой `puts` (с префиксом `[MACRO]`).

## 5. Язык сценариев (Tcl)

Файл сценария — это Tcl-программа. При запуске/перечитывании модуль выполняет файл
**по командам верхнего уровня** (по одной, в том же интерпретаторе), поэтому процедуры и
переменные объявляются до правил и доступны в их телах.

### Регистрация правил (команды верхнего уровня)

```tcl
cron {<cron-выражение>} {<тело>}   ; «момент времени» — по расписанию
cond {<Tcl-условие>} {<тело>}      ; «условие» — по фронту ложь→истина
term {<слова...>} {<тело>}         ; «событие из терминала» (macro msg)
button {<имя>} {<тело>}            ; «кнопка» (macro btn, web fire)
```

- `cond` проверяется раз в секунду; тело выполняется один раз при переходе
  условия в «истину» и не повторяется, пока условие остаётся истинным.
- `term`/`button` срабатывают только у **запущенных** файлов и только при полном
  совпадении спецификатора со всеми словами события.

### Доступные команды и значения
- `set имя значение`, чтение `$имя`;
- `proc имя {арг...} {тело}` — свои функции (внутри файла);
- `if`, `while`, `return`, `break`, `continue`, `subst`;
- `puts текст` — вывод в терминал с префиксом `[MACRO]`;
- `now` — текущие секунды; `clock` — время «ЧЧ:ММ:СС»;
- арифметика и сравнения: `+ - * /` и `> >= < <= == !=`;
- синтаксис: `[команда]` — подстановка результата; `{...}` — группировка без подстановки;
  `"..."` — подстановка; `#` — комментарий до конца строки.

### Простой пример

```tcl
# считаем тики каждые 10 секунд
set ticks 0

proc say {msg} {
    puts [clock]
    puts $msg
}

cron {*/10 * * * * *} {
    set ticks [+ $ticks 1]
    say {fired: every 10 seconds}
}

cond {[>= $ticks 6]} {
    say {fired: already 6 ticks}
}
```

Тело может состоять из нескольких команд на разных строках — модуль исполняет их
последовательно (в т.ч. внутри `proc`).

## 6. Справка по CRON

Выражение — **6 полей** (интерпретатор всегда ожидает секунды первым):

```
секунды   минуты   часы   день-месяца   месяц   день-недели
```

- секунды 0–59, минуты 0–59, часы 0–23;
- день месяца 1–31, месяц 1–12 (или `JAN`–`DEC`), день недели 0–7 (0 и 7 = воскресенье,
  или `SUN`–`SAT`);
- возможны 5 полей (без секунд — станут 0) и 7 полей (год опционально).

Синтаксис поля: `*` — любое; `*/N` — каждые N; `a-b` — диапазон; `a-b/N` — шаг в
диапазоне; `a,b,c` — список; `?` — как `*`.

### Примеры

```tcl
cron {*/10 * * * * *}     { ... }   # каждые 10 секунд
cron {0 * * * * *}        { ... }   # каждая минута (в 0-ю секунду)
cron {15 42 * * * *}      { ... }   # каждый час в 00:42:15
cron {0 0 * * * *}        { ... }   # каждый час в 00:00:00
cron {0 0 */2 * * *}      { ... }   # каждые 2 часа
cron {0 30 */4 * * *}     { ... }   # каждые 4 часа в :30 (00:30, 04:30, ...)
cron {0 0 9 * * 1}        { ... }   # по понедельникам в 09:00
cron {0 0 9 * * 1,2,4}    { ... }   # пн+вт+чт в 09:00
cron {0 0 9 * * 1-5}      { ... }   # будни в 09:00
cron {0 0 9 2-30/2 * *}   { ... }   # чётные числа месяца в 09:00
cron {0 0 9 5 * *}        { ... }   # 5-го числа каждого месяца в 09:00
cron {0 0 9 */5 * *}      { ... }   # 1,6,11,... числа месяца в 09:00
cron {0 0 9-17 * * *}     { ... }   # каждый час с 09:00 до 17:00 включительно
cron {0 0 9-17 * * 1-5}   { ... }   # будни с 09:00 до 17:00
```

Cron срабатывает **только после синхронизации NTP**; расписание считается в локальном
времени. Планировщик хранит у каждого cron-правила «следующий момент» (`cron_next` из
ccronexpr), при совпадении `now() >= next` выполняет тело и сразу считает следующий
момент — пропущенное не «догоняется».

## 8. Как это устроено внутри

### Поток данных

```
web (/macros.html) ──GET──▶ web_Init-эндпоинты  → только FS + /config_macros.json + флаг
                                      │
                              SetTimerTask(tick, 1000)   (main loop)
                                      │
              изменение списка (gen) → пересборка набора запущенных сценариев
                                      │
        для каждого запущенного файла (свой struct tcl* и таблица сущностей):
          cron:  now() >= next        → тело; next = cron_next(expr, now())
          cond:  вычислить условие, фронт false→true → тело
          term/button: события из очереди (терминал/HTTP) → тело
```

- Интерпретатор (pTcl) и планировщик вызываются **только в main-loop контексте**
  (тик EERTOS и терминал); веб-обработчики не трогают интерпретатор — они меняют
  мету/FS и поднимают счётчик, а тик пересобирает сценарии.
- Каждый файл получает **свой** `struct tcl` (переменные/proc не «протекают» между
  файлами), правила регистрируются в таблицу сущностей файла.
- В pTcl доработаны: поддержка комментариев `#`, защита от «зависаний»
  (лимиты `TCL_MAX_DEPTH`/`TCL_MAX_STEPS`), исполнение многострочных скриптов
  «по командам», корректное освобождение памяти при удалении команд.

### Структуры данных (module_macros.h)

- `MacroFile` — файл-сценарий: метаданные (`name`, `prio` 0..7, `run`, `created`) +
  runtime (`tcl`, `active`, `err`, таблица сущностей).
- `MacroEntity` — правило: `type` (cron/cond/button/term), `spec`, `body`,
  для cron — разобранное выражение `cron_expr` и `next`.
- `strMacrosConfig` — `enabled`.
- Ограничения: ESP32 — до 16 файлов × 24 сущности; ESP8266 — 8 × 8 (лимиты в заголовке).

### Метафайл `/config_macros.json`

```json
{
  "enabled": true,
  "files": [
    { "name": "/macros/ex_10s.tcl", "prio": 7, "run": false, "created": 1788545122 }
  ]
}
```

Список для веба = сканирование `/macros/*.tcl` + наложение меты (новые файлы
авто-добавляются, записи про отсутствующие удаляются). Размер файла берётся при
формировании списка.

### Файлы модуля

| Файл | Роль |
|------|------|
| `module_macros.h/.cpp` | класс `CLASS_MODULE_MACROS`, мета-список, парсер, тик, веб, терминал |
| `tcl.c` / `tcl.h` | вендоренный pTcl (доработан) |
| `ccronexpr.c` / `.h` | вендоренный cron-парсер (supertinycron) |
| `cron_time_bridge.cpp` | функции времени ccronexpr на базе `common/TimeLib` |
| `module_macros.ini` | env-окружения `esp32_macrotest`, `esp8266-macrotest` |
| `web/macros.html` | веб-менеджер (таблица, кнопки, drag колонок, справка CRON/Tcl) |
| `web/config_macros.json` | дефолтный мета-конфиг в образе FS |
| `web/macros/*.tcl` | файлы-примеры сценариев |
| `module_macros_version.h` | версия модуля (автогенерация) |

## 9. Ограничения прототипа (важно)

- pTcl исполняет «тело» по командам; сложные вложенные конструкции `if`/`while`
  с несколькими командами поддерживаются ограниченно (рекомендуется выносить логику
  в `proc` и вызывать её одной командой).
- Интерпретатор использует heap (`malloc`); на ESP8266 следите за свободной памятью.
- Приоритет 0..7 пока информационный (сортировка/порядок исполнения в будущем).
- Перечитывание файлов — только вручную (старт/стоп/кнопка «Перечитать»/терминал);
  авто-детекта изменения файла по mtime нет.
- Cron требует синхронизации NTP (время локальное); `cond`/`term`/`button` работают без NTP.
- Перепрошивка FS-образа перезаписывает пользовательские правки (файлы сценариев и
  мета-конфиг восстанавливаются из сборки) — стандартное поведение проекта.
- В терминал выводится только латиница (в коде — русские комментарии, в веб — русский
  интерфейс).
